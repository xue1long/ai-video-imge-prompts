# 2026-11-03

## 每日采集流水线：修复 `git commit --only` 静默漏掉新文件

每日自动化跑 `scripts/daily_collect.py`（midjourney-explore 站），退出码 0、已推送，
但**实际漏了 4 个文件**：`data/daily/2026-11-03/{jobs,meta}.json` 与两个新 aspect 页
（`3-5`、`70-99`）。

### 根因

`git commit --only -- <paths>` 只提交**已被 git 跟踪**的路径；未跟踪的新文件被**静默跳过，
退出码仍是 0**。这个坑是 `1effd23`（提交隔离改造）引入的：改用 `--only` 保住了「不碰暂存区」，
但没考虑新文件 —— 而新批次目录 `data/daily/<日期>/` 每天新建，必然踩到。

**为什么不能只看退出码**：manifest.json 已含该批次作业数，批次源文件却没入库 →
干净检出上 `tests/run.py::test_manifest_covers_all_daily` 断言失败（600 != 400），CI 变红。
脚本却报成功。

### 修复（`scripts/daily_collect.py`）

在变更检测**之前**用 `git add --intent-to-add`（-N）登记新文件，再走 `git commit --only`。

- `-N` 只登记路径、不写内容 → 保住「不碰暂存区」的隔离承诺（实测：别人已暂存的文件提交后仍留在暂存区）。
- **必须前移到变更检测之前**：`git diff --quiet` 看不见未跟踪文件，否则「本次只有新增文件、
  已跟踪文件都没变」会被误判成「无变更，无需提交」整批漏掉 —— 那正是新批次首日的典型形态。
  登记后 diff 才看得见新文件。

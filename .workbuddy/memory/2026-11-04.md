## 傍晚续：第三轮干净检出验证（修正验证方法本身）

上一轮的「全绿」结论**有一半是假的** —— 验证方法有缺陷。这次重做，过程与结论如下。

### 验证方法的三处缺陷（比代码 bug 更值得记）

**缺陷 1：`git checkout-index` 检出的也是 HEAD，工作区改动一个都进不去。**
用它构造检出副本 = 「旧代码 + 新测试」，4 个测试立刻假红
（`full_path` KeyError、`799 != 800` 等）—— 那些红不是 bug，是验证方法错了。

**缺陷 2：Windows 上 `git clone --local` 走硬链接会失败** ——
`fatal: failed to create link ...: Improper link`。必须加 `--no-hardlinks` 走普通拷贝。

**缺陷 3：补丁以「未暂存改动」形式留在检出副本里时，`git diff --exit-code` 必然红。**
闸门比的是「构建产物 vs 仓库」，前提是改动**已提交**。补丁未提交时，
diff 会把本轮全部改动都算作差异（实测 21 个文件、13548 行删除），
而且 `--ignore-cr-at-eol` 前后完全一样 —— 说明**不是行尾漂移**，是方法错。

正解四步（脚本按此重写，用完即删）：
1. `git clone --no-hardlinks --no-checkout` + `checkout HEAD`
2. `git diff --binary HEAD` → patch → `git apply --binary`（带上工作区对已跟踪文件的全部改动，含删除）
3. 复制 `git ls-files --others --exclude-standard` 的未跟踪文件（`git diff` 抓不到）
4. **在临时克隆里 `add -A` + `commit`**（只动临时目录）—— 第 4 步的前提

扫描口径：**只扫入库的文本文件**（`git ls-files` 过滤掉 `sites/*/data/` 的大 JSON），
否则 grep 会撞进 100 MB+ 的 `data/prompts_*.json` 而截断输出。

## 傍晚续：拆成 4 个提交并逐个验证

用户说「提交」。本轮把 37 项改动 + 6 个新文件拆成 **4 个提交**，每个都验证过自洽。

### 拆分依据

改动天然分三个主题（落地页删除 / prompthero 去 full 档 / 文档口径），
外加一个独立的第四块（采集器退出码契约 + manifest 口径修正）。
拆分的硬约束：**每个提交都必须自洽** —— CI 闸门 4 要求「构建产物与仓库一致」。

### 拆分时踩到的三个坑

**坑 1：hub 产物跨主题。** `hub/build_hub.py` 的 `total_images()` 读 `sites.json` 的 `tiers`，
prompthero 去 full 让总数从 128,929 变 115,931 —— hub 产物同时依赖两个主题。
解法：**逐提交重建**，每个提交前用该提交对应的中间态配置重建一次。
提交 1 的中间态总数是 128,929，提交 2 才是 115,931。

**坑 2：拆 `tests/run.py` 不能用 `git apply` 单个 hunk。**
patch 的 hunk 头带行号，单独 apply 会 "patch does not apply"（行号对不上）；
而且 hunk 内的**删除行可能分散在上下文之间**（hunk 1 就是），
只取连续的 `-` 行会得到不连续的文本，永远命中不了。
正解：**整块替换** —— 旧块 = hunk 内所有非 `+` 行，新块 = 所有非 `-` 行，
从 HEAD 版出发逐块替换，每步断言命中次数为 1。
hunk 3 里混了 MidRule（提交 2）与 Docs（提交 3），按 ` class Docs(unittest.TestCase):`
标记行切开。校验：累积到最后一个提交时与工作区原版**逐字节一致** → 拆分无损。

**坑 3：`-N` 的另一面（记忆第 10 条的补充）。**
`git add --intent-to-add` 登记后跑**普通** `git commit`，那些文件**不会进提交** ——
`-N` 只在索引里登记路径与空 blob，内容没写进去。`git show --stat` 里看不到它们，
提交看起来成功。ADR 4 篇就这么丢了一次，补了一个 commit 才进去。
**`-N` 只用于「不碰暂存区的隔离提交」**；要真正入库必须用普通 `git add`。
每次提交后用 `git show --stat HEAD` + `git ls-tree HEAD <dir>` 双重复核。

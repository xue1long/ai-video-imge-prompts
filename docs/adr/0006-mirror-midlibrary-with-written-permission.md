# 镜像 Midlibrary 风格库（站方书面许可）

编号 0006 · 2026-11-05

新增站点 `midlibrary`（Midlibrary 风格库，MIDLIB-01）：Midjourney 风格名与风格参考码（SREF）的索引，
**上游 10,142 条**（5,504 个风格名 + 4,638 个 SREF 码；本站收 10,140 条 —— 少的 2 条上游自己没有
v8.2 样例表，不伪造图故未收），每条附一行可复制的提示词与一张示例图。
上游条款默认禁止批量抓取、再发布图片与建数据集 —— 镜像只有在拿到站方**书面许可**后才成立，
许可已于 **2026-11-05** 到手。

## 背景

**需求是真的。** Midjourney 用户查风格名与 SREF 码是日常动作，但上游的可用性有限：
条目散在 **212 页**分页里（每页 48 条），没有中文索引，
而「这个码长什么样」只能靠示例图判断 —— 示例图正是原站每条都在展示的东西。

**上游条款默认是禁止的。** Midlibrary 的 Terms of Use（2026-11-02 生效，
<https://midlibrary.io/midlibrary/terms-of-use>）把「可以用什么」和「不可以做什么」分得很清：

- 可以：复制风格名、SREF 码与提示词，用在自己的创作里（包括卖出去的作品）；
  分享指向 Midlibrary 页面的链接。
- 不可以（**未经书面许可**时）：批量抓取或下载、再发布其图片 / 页面 / 指南、
  据此复制出这个库或建成数据集、用其图片与页面训练 AI 模型、绕过站点的限额与安全措施。

也就是说：**文本层本身可以随便用，但「把库镜像过来并把图存一份」正好是被禁止的那一侧。**

**许可到手的时点与范围。** 站方已出具书面许可，出具时间记作 **2026-11-05**，
范围是**个人学习用途**的镜像：文本层（名称 / 分类 / 提示词 / SREF 码）
+ 图片层（缩略图与中图两档），条件为**署名 + 回链原站**。
许可原件由站方与本站维护者保存，详情可向上游或本站维护者索取。

**许可到位之前的那一阶段**只跑了「站方精选」的 554 条小切片，用来先验证
抓取 → 清单 → 取图 → 构建 → 发布这条链路。**这是为了先验证全链路，
不是为了规避条款** —— 条款禁止的是未经许可的批量抓取，不是「先做小切片」。

## 选择

镜像一个「**风格名 + SREF 码 + 可复制提示词 + 示例图**」的索引站：

- **授权徽章取 `conditional`**（入口页显示「有条件」），条件 = 署名 + 回链 + 仅个人学习用途；
- **文本层**：名称、slug、类型（7 种 kind）、分类（16 个）、提示词 / SREF 码、三个徽章
  （站方精选 / 公有领域 / 已实测），原样保留、不翻译；
- **图片层两档**：`thumb`（320px 象限，样例表的一角）与 `mid`（960px 整张样例表），
  **没有 full 档**，全尺寸回原站看；
- **图片存本地，不热链**：两档都是 `local-only`；
- **采集只走公开 HTML 页面**：上游是 Next.js App Router（数据在 RSC flight payload 里，
  没有公开 JSON 接口），`robots.txt` 只禁 `/api/`，本站不碰接口。

## 理由

**为什么值得做。** 三条：

1. 需求真实且上游供给不便 —— 212 页分页、没有中文索引；码与提示词按上游条款
   本来就是拿来用的，索引等于把「找码」这件事做快。
2. 规模与信息量撑得起一个站 —— 上游 10,142 条（本站收 10,140 条）、16 个分类、7 种 kind，
   且每条都有
   **可复制的提示词**与**示例图**，比只存一串 `--sref` 数字强得多。
   （对照 [0005-remove-mj-styles-site.md](0005-remove-mj-styles-site.md)：
   那条数据线被删是因为「一个码 + 三张语义示例图，没有提示词、没有作者」撑不起独立站点；
   本站的信息量与它不是一回事。）
3. 这次有**书面许可**，不是灰色镜像 —— 上游条款禁止的那几件事（bulk scrape、
   republish pictures、build a dataset）在许可范围内不再适用。

**为什么必须先拿许可。** 没有许可就做这件事，等于同时踩中三条禁令：
批量抓取整个库、再发布其图片、以及据此建成一个库的数据集。许可到位后，
镜像才从「违反条款」变成「条款明确允许的用法」；条件（署名 + 回链 + 仅个人学习用途）
必须同时写进 [NOTICE.md](../../sites/midlibrary/NOTICE.md) 与页面页脚，
并用 `conditional` 徽章在入口页上把「有条件」显示出来。

**为什么图片要存本地而不是热链。** 这一条**不是取舍，是能不能的问题**：
上游图片有 Referer 门 —— 不带 Referer 一律 403（Cloudflare 挑战页），
Referer 必须是 https 且 host 为 `midlibrary.io`；
外站热链会被上游的 Worker 挡掉，返回 `Pictures are shown on midlibrary.io.`。
⇒ 页面上写上游图片地址，在浏览器里就是裂图。热链方案技术上不成立，
所以两档都存本地（`local-only`），页面给「打开原站 ↗」回链。

**为什么不做 full 档。** 原图 2048×2048 太大，且上游大图断流严重（960 / 1440 / 2048
三档都遇到过 180 秒超时只收到部分字节）。留两档够用，全尺寸回原站看。

## 考虑过的替代方案

| 方案 | 否决理由 |
| --- | --- |
| **只收录文本层**（名称 / 码 / 提示词），不存图 | 省 2.5 GB 磁盘，但「这个码长什么样」只能靠想象 —— 而上游每个条目都靠示例图说明。许可**已经明确允许**图片层，不存图等于放弃许可给的东西 |
| **图片热链上游** | 技术上**不成立**：外站热链被上游的 Worker 挡掉，返回 `Pictures are shown on midlibrary.io.`（403）。这不是取舍问题 |
| **连 full 档（2048px）一起存** | 全量十几 GB 起步，且上游大图断流严重（180 秒超时只收到部分字节），稳定性与磁盘都不划算 |
| **只做「站方精选」的 554 条**，不做全量 | 规模撑不起一个站。554 条只是许可到位前的链路验证，不是最终形态 |
| **做成可下载的数据集** | 上游条款明令禁止（未经书面许可不得 build a dataset）；且许可只覆盖个人学习用途的索引镜像 |
| **不做这个站**（像 `mj-styles` 那样删掉） | 前提不同：`mj-styles` 是无许可的灰色抓取、且只有「码 + 示例图」没有提示词；本站有书面许可，每条都带**可复制的提示词 + 示例图** |
| **等条款放宽再抓，不申请许可** | 条款没有放宽的迹象（「We may limit or block automated access」），而且**码与提示词能用、图片不能存**这件事本身就是许可的正当理由 |

## 后果

- **本地磁盘增加约 2.5 GB**（thumb + mid 两档）。图片按仓库惯例不入 git
  （`.gitignore` 排除 `sites/*/thumbs/`、`sites/*/mid/`），首次部署用
  `python tools/fetch.py --site midlibrary` 拉取，之后幂等跳过。
- **取图必须带 Referer**，由站点级取图钩子 `sites/midlibrary/scripts/fetch_hook.py` 处理
  （钩子的第三个可选函数 `fetch_bytes`，自带 240 秒长超时与 4 次重试）——
  **不改 `tools/`**（`AGENTS.md` 规则 1：`tools/` 不写单站分支）。
- **上游慢且会断流**，采集要带重试与完整性校验：列表页校验 `</html>` 结尾再入库，
  取图重试；并发压到 4、请求间隔 0.35 秒，不打疼一个非营利站。
- **先 554 条小切片验证再全量**：许可到位前只跑「站方精选」的 554 条，
  目的是先验证全链路，不是规避条款；许可到手后才按许可范围做全量采集。
- **许可条件写进 NOTICE 与页面页脚**：署名 + 回链 + 仅个人学习用途；
  入口页授权徽章显示「有条件」（`sites.json` 的 `license: "conditional"`）。
- **数据是快照**：上游新增的条目不会自动出现，重跑采集脚本才更新。
- **可撤下**：上游条款允许被点名的艺术家要求撤下其姓名与页面（站方 30 天内处理）——
  撤回时按 slug 定位条目即可整条下线。
- **本决策的失效条件**：许可被撤回或收窄时，本站须整站下线（删除站点条目与站目录）。
  届时的下线动作不需要再开一条 ADR —— 这条 ADR 就是它存在的理由。

# mj-styles 不生成静态落地页

风格码库里没有可枚举的分类（原站只有一个搜索框），唯一稳定的分组维度是「这张示例图属于哪种构图」（人像 / 风景 / 静物），而这个维度已经由首页顶部的全站构图切换器覆盖了 —— 落地页的 CTA 带 `#kind=<slug>`，语义恰恰就是「全站切到该构图」，与首页切换器完全重复。2026-11-04 决定删除该站的落地页，并给 `sites.json` 引入 `"landing": false` 作为站能力声明：声明为 `false` 的站不写落地页、hub 不链它的 `browse/`、sitemap 不列它的 URL。

## 考虑过的替代方案

| 方案 | 否决理由 |
| --- | --- |
| 保留落地页 | 每个落地页只是首页的一个子集视图，没有提供首页没有的信息 |
| 换个维度做落地页（风格类别 / 收录时间） | 码表里没有可靠的类别字段；按 `added_at` 分是「快照历史」，规模更薄 |
| 连 `#kind=` 定位能力一起删 | hash 定位是主画廊的通用能力，其余站都在用。留着比删掉更一致 |

## 后果

- 首页**仍然读 `location.hash`** —— 用户可以在地址栏敲 `#kind=still-life` 切构图。这条能力与落地页在不在无关，落地页删除不动它。
- `shared/landing.py` 的 `write_site()` 现在接受空分面列表，语义是「这个站不要落地页」：写一份空的 `landing.json`（release.py 与 sitemap 据此收敛），并清掉上次生成的页面。
- `tests/run.py` **双向**校验：声明 `landing: false` 的站必须没有落地页且磁盘上不留落地页目录；声明 `true` 或未声明的站必须有。
- 落地页是搜索引擎与 AI 读到的入口。少这一站的分面页是有意的取舍 —— 该站的价值在码表本身（可复制、可搜索），不在分类浏览。

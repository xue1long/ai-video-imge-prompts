# 缺图不阻断构建

`mj-styles` 的构建原本在缺图时硬失败（列出缺什么、非零退出）。2026-11-04 改为：缺图照常打到 stderr 列出清单，页面照常生成，退出码 0。

## 为什么改

两条理由，第二条更要紧：

1. **CI 的干净检出上必然缺图。** 图片不进仓库（`.gitignore` 排除了 `sites/*/styles/`），CI 检出后本地一张图都没有。硬失败意味着这条闸门永远红。
2. **构建产物只取决于配置。** 这是本仓库的一条既有约束（见 `AGENTS.md` 的取图策略条目与 `shared/image_policy.py` 的模块注释）：策略是提交进仓库的静态配置，构建过程不探测本地文件是否存在。同样的代码在有图与无图的环境里必须产出**同一份页面** —— 硬失败会让本地（有图）与 CI（无图）走两条不同的路，产出自相矛盾。

## 考虑过的替代方案

| 方案 | 否决理由 |
| --- | --- |
| 保持硬失败 | CI 永远红 |
| 缺图时静默降级（用 1024 档顶替） | 页面会慢一倍，且**看不出问题** —— 发布出去才发现 |
| 缺图时硬失败，但 CI 上跳过该站 | 闸门缩水，且掩盖了真实构建错误 |
| 缺图只警告（采用） | 构建产物稳定，缺图清单仍然可见 —— 人能看见 |

## 后果

- 构建脚本里缺图检查的返回值不再是构建的成败依据，只是一段 stderr 告警。**告警不能被吞掉** —— 打印到 stderr 而不是 stdout，就是为了在 CI 日志里仍然显眼。
- 「构建产物只取决于配置」这条约束现在有了两个应用点：取图策略不探测文件存在性，缺图不阻断构建。两者指向同一件事：**有图与无图必须产出同一份页面**。
- 缺图与「视图隐藏」不是一回事：视图隐藏是条目在页面上不显示但文件还在；缺图是文件已经不在磁盘上。见 `CONTEXT.md`。
